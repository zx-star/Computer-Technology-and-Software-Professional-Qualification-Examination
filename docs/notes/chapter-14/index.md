## 1 软件可靠性基本概念

- **定义**：软件可靠性 = 软件产品`在规定的条件下、规定的时间区间内完成规定功能`的能力（三个"规定"：条件、时间、功能）。
- **与硬件可靠性的区别**（4 点，易考对比）：
  - 复杂性：`软件复杂性比硬件高`，大部分失效来自软件失效。
  - 物理退化：硬件失效主要是物理退化，`软件不存在物理退化`。
  - 唯一性：`软件是唯一的`，每个 COPY 版都一样；两个硬件不可能完全一样。
  - 版本更新周期：`硬件较慢，软件较快`。
- **定量描述**：
  - 规定时间三类：`自然时间、运行时间、执行时间（占用CPU）`。
  - 失效概率：初始为 `0`，随时间`单调递增`、不断趋向 `1`。
  - 可靠度：规定条件下、规定时间内`不发生失效的概率` = `1 - 失效概率`。
  - 失效强度：`单位时间`内软件系统出现失效的概率。
- **三个时间指标**（必背）：

| 指标 | 含义 | 说明 |
| --- | --- | --- |
| MTTF 平均失效前时间 | <span class="course-highlight">平均无故障时间</span> | 发生故障前正常运行的时间 |
| MTTR 平均恢复前时间 | <span class="course-highlight">平均故障修复时间</span> | 发生故障后的修复时间 |
| MTBF 平均故障间隔时间 | <span class="course-highlight">失效或维护中所需的平均时间</span> | 含故障时间 + 检测、维护设备的时间；`MTBF = MTTF + MTTR` |

- **系统可用性** = `MTTF / (MTTF + MTTR) × 100%`。
- **串并联系统可靠性**（公式必背）：
  - 串联：一个设备不可靠 → 整个系统崩溃；<span class="course-highlight">`R = R1 × R2 × … × Rn`</span>（可靠性逐级相乘，越串越低）。

    ![串联系统可靠性图](./series-system-reliability.png)

  - 并联：所有设备都不可靠 → 整个系统才崩溃；<span class="course-highlight">`R = 1 - (1-R1) × (1-R2) × … × (1-Rn)`</span>（先算全失效概率再取补）。

    ![并联系统可靠性图](./parallel-system-reliability.png)
- **失效严重程度类**：影响程度不仅取决于`失效发生的概率`，还和`失效的严重程度`有关；严重程度类 = `对用户具有相同程度影响的失效集合`；分级标准常见`对成本影响、对系统能力的影响`（成本影响：额外运行成本、修复和恢复成本、业务机会损失），等级通常用`数量级`划分。

## 2 软件可靠性建模

- **定义**：软件可靠性模型 = `为预计或估算软件的可靠性所建立的可靠性框图和数学模型`。
- **主要影响因素**：`缺陷的引入、发现和清除`——引入取决于`产品特性 + 开发过程特性`（开发技术/工具、人员水平、需求变化频度）；发现依靠`用户操作方式、运行环境`（即运行剖面）；清除`依赖失效的发现和修复活动及可靠性投入`。技术角度 5 项：`运行环境、软件规模、软件内部结构、开发方法和开发环境、可靠性投入`。
- **模型 4 组成部分**：`模型假设、性能度量、参数估计方法、数据要求`。
- **3 个共同假设**：`代表性假设`（测试数据可预测运行阶段行为）、`独立性假设`（失效在不同时刻独立发生、互不影响）、`相同性假设`（不区分失效严重等级）。
- **好模型 5 特性**：基于可靠的假设、简单、计算有用的量、映射未来失效行为、可广泛应用。
- **模型分类（10 类，了解即可）**：
  1. 种子法：捕获-再捕获，"播种"错误，按发现比例估计残留错误数。
  2. 失效率类：研究程序的失效率。
  3. 曲线拟合类：回归分析研究缺陷数、失效率、失效间隔时间。
  4. 可靠性增长：增长函数预测检错过程中的可靠性改进。
  5. 程序结构分析：按调用关系建可靠性分析网络（结点=模块，有向弧=执行顺序）。
  6. 输入域分类：样本点使用概率 → 使用可靠性。
  7. 执行路径分析：各逻辑路径执行概率 → 使用可靠性。
  8. 非齐次泊松过程：单位时间失效次数为独立泊松随机变量。
  9. 马尔可夫过程：完全/不完全改错的线性死亡模型等。
  10. 贝叶斯：失效率试验前分布 + 当前测试失效信息。
- **Musa/Okumoto 5 属性分类**：`时间域`（自然时间/CPU 时间）、`失效数类`（有限/无限）、`失效数分布`（泊松/二项）、`有限类`、`无限类`。

## 3 软件可靠性管理

- **定义**：软件工程管理的一部分，`以全面提高和保证软件可靠性为目标`、`以软件可靠性活动为主要对象`，是把现代管理理论用于软件生命周期中可靠性保障活动的管理形式。
- **内容**：`各阶段可靠性活动的目标、计划、进度、任务和修正措施`。
- **各阶段任务**（共同动作：收集数据、调整计划/模型、编制文档）：
  - 需求分析：可靠性目标、影响因素、验收标准、框架、文档编写规范、初步计划、数据收集规范。
  - 概要设计：可靠性度量、详细验收方案、可靠性设计。
  - 详细设计：可靠性设计、预测。
  - 编码：可靠性测试（单元）、排错。
  - 测试：可靠性测试（集成和系统）、排错、可靠性建模、评价。
  - 实施：可靠性测试（验收）、排错、调整模型、评价。

## 4 软件可靠性设计

- 保障可靠性`最有效、最经济、最重要`的手段 = 在`软件设计阶段`采取措施进行可靠性控制。
- **定义**：在`常规软件设计中`应用各种方法技术，兼顾用户功能/性能需求的同时`全面满足软件的可靠性要求`。
- **设计原则（3 条）**：①是`软件设计的一部分`，在总体设计框架中使用，不与其他设计原则冲突；②前提满足提高软件质量的要求，最终目标 = `提高和保障软件可靠性`；③应`确定软件的可靠性目标`，不能无限扩大化，排在`功能度、用户需求、开发费用`之后考虑。
- **主要设计技术**：`容错设计、检错设计、降低复杂度设计`。

- **三大设计技术详解**：
  - **容错设计**：主要方法 = `提供足够的冗余信息和算法程序`，运行时及时发现设计错误并采取补救措施；3 种方法：`恢复块设计、N版本程序设计、冗余设计`。
    - 恢复块（动态冗余）：选一组操作为容错单元，`功能相同、设计差异`的多个文本任一时刻只有一个运行，故障则换备份文本。
    - N版本：`多个模块/版本，相同输入下实行多数表决`，防单版本故障给出错误服务；前提：`需求说明完全且精确、设计全过程不相关`；新增 3 阶段：`相异成分规范评审、相异性确认、背对背测试`。
  - **冗余设计**：完整系统之外用`不同路径/算法/实现方法`的模块或系统做备份，故障时替换。
  - **检错技术**：故障后`及时发现并报警`提醒维护人员；代价低、不能自动解决；要素：`检测对象、检测延时、实现方式、处理方式`。
  - **降低复杂度**：复杂性 = `模块复杂性`（内部数据流向 + 程序长度）+ `结构复杂性`（模块间关联程度）；复杂度超阈值 → 缺陷激增、可靠性骤降；思想：保证功能前提下`简化结构、缩短代码、优化数据流向`。
  - **系统配置技术**（系统级容错）：`双机热备 + 服务器集群`。
    - 双机热备：`软硬件结合`方案 = 2 台服务器 + 共享磁盘阵列 + 热备软件；数据经磁盘阵列集中管理和备份；`心跳`机制（主从按固定间隔互发信号，失联即把资源转给备机）；模式：`一主一备 / 互为备份 / 双工同时运行`。
    - 集群：`多台计算机协同工作`，每台承担部分计算 + 容错任务，故障节点隔离 + `负载转嫁`；特点：`可伸缩、高可用、可管理、高性价比、高透明`；分类：`高性能计算、负载均衡、高可用性`。
    - 负载均衡：集群关键技术，目标`加快响应速度、提高客户端访问成功概率`，让节点负荷平均；5 种：①特定软件（应用层，HTTP 重定向）②DNS（传输层，同主机名按序返回不同解析）③NAT（外部 IP 映射多个内部 IP）④反向代理 ⑤混合型。
- **恢复块 vs N版本（表 19-1，了解）**：

| | 恢复块方法 | N版本程序设计 |
| --- | --- | --- |
| 硬件运行环境 | 单机 | 多机 |
| 错误检测方法 | 验证测试程序 | 表决 |
| 恢复策略 | 后向恢复 | 前向恢复 |
| 实时性 | 差 | 好 |

## 5 软件可靠性测试与评价

### 可靠性测试的意义（5 点）

1. 软件失效可能造成`灾难性的后果`。
2. 软件失效在`整个计算机系统失效`中的比例较高。
3. `软件可靠性技术很不成熟`，加剧了软件可靠性问题的重要性。
4. 软件可靠性问题是`造成费用增长的主要原因之一`。
5. 软件对`生产活动和社会生活`的影响越来越大 → 可靠性问题在软件工程乃至整个计算机工程领域的重要性上升。

### 广义 vs 狭义可靠性测试（对比必背）

| 范围 | 目的 | 方式 |
| --- | --- | --- |
| 广义 | <span class="course-highlight">最终评价软件系统的可靠性</span> | `建模、统计、试验、分析和评价等一系列手段`（= 测试 + 建模 + 评价，见流程图下半部分） |
| 狭义 | <span class="course-highlight">获取可靠性数据</span> | `按预先确定的测试用例`、在`软件的预期使用环境中`；面向缺陷的测试，以用户将要使用的方式测试（见流程图上半部分） |

![软件可靠性测试过程图](./reliability-testing-process.png)

### 可靠性测试的目的（3 点）

1. `发现`软件系统在需求、设计、编码、测试和实施等方面的`各种缺陷`。
2. 为软件的`使用和维护提供可靠性数据`。
3. 确认软件`是否达到可靠性的定量要求`。

### 可靠性测试过程

- 组成：`可靠性目标的确定、运行剖面的开发、测试用例的设计、测试实施、测试结果的分析`。
- 步骤：`定义运行剖面（建模使用行为）→ 设计可靠性测试用例 → 实施可靠性测试`。

### 软件可靠性评价（3 过程）

- `选择可靠性模型、收集可靠性数据、可靠性评估和预测`。
- 选模型看：`假设适用性、预测能力与质量、输出值能否满足评价需求、使用简便性`。
- 数据收集 = `软件失效数据`（测试、实施阶段）；5 个问题：`规范不统一、连续性不保证、缺乏有效手段、完整性不保证、质量准确性不保证`；对策：`及早定模型、制订可实施收集计划、重视整理分析、用数据库存储和统计`。
- 评估和预测：`是否达到可靠性目标、未达还要再投入多少`；运行一年或若干时间后能否达到交付（或部分交付）可靠性水平；辅助：`失效数据图形分析法、试探性数据分析技术`。
