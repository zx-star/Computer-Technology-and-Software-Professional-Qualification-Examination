## 1 计算机系统组成

- 计算机系统 = 用于数据管理的`计算机硬件、软件及网络`组成的系统，按人的要求接收和存储信息，自动进行数据处理和计算，并输出结果。

## 2 计算机硬件

### 2.1 处理器

- 冯诺依曼 5 大组成部分：`控制器、运算器、存储器、输入设备、输出设备`；`运算器和控制器是处理器的核心部件`。
- 指令集按复杂程度分：`复杂指令集（CISC，Complex Instruction Set Computer）`和`精简指令集（RISC，Reduced Instruction Set Computer）`。
- 专用处理器：`图形处理器（GPU，Graphics Processing Unit）`有`数百或数千个内核`、`并行运行大量计算`，用于深度学习/机器学习；`信号处理器（DSP，Digital Signal Processor）`专用于实时数字信号处理；`现场可编程逻辑门阵列（FPGA）`。

### 2.2 存储器

- 按`与处理器的物理距离`分 4 个层次：
  1. `片上缓存`：处理器核心内直接集成，SRAM 结构，16kB~512kB，分一级或二级。
  2. `片外缓存`：核心外，经交换互联开关访问，SRAM，256kB~4MB，L2/L3（平台 Cache）。
  3. `主存（内存）`：DRAM 结构，独立部件/芯片，经总线与处理器连接，依赖充电维持数据（掉电丢失），数百 MB~数十 GB。
  4. `外存`：磁带、磁盘、光盘、Flash 等，`访问速度慢，但容量大，掉电后能保持数据`。

### 2.3 总线与接口

- 总线 = 计算机部件间`遵循某一特定协议实现数据交换的形式`。按位置分`内总线、系统总线、外部总线`：内总线 = `芯片内部互连`（片上/片内总线）；系统总线 = `CPU、主存、I/O 接口`的总线（广义含级联的`局部总线`）；外部总线 = `计算机板和外部设备之间或计算机系统之间`互联（通信总线）。总线间经`桥`连接（实现总线协议转换）。
- 性能指标：`总线带宽、总线服务质量 QoS、总线时延、总线抖动`。
- 种类：`并行总线`（PCI、PCIe、ATA/IDE）；`串行总线`（USB、SATA、CAN、RS-232、RS-485、RapidIO、以太网等）。
- 接口 = `同一计算机不同功能层之间的通信规则`：显示类（HDMI、DVI）、音频类（TRS、RCA、XLR）、网络类（RJ45、FC）、PS/2、USB、SATA、LPT 打印、RS-232 等；`一种总线可能存在多种接口`。

## 3 计算机软件

### 3.1 软件分类

- 分`系统软件和应用软件`：系统软件 = `不依赖特定应用领域的通用软件`，控制管理软硬件资源、提供服务；应用软件 = `为某类应用或某个特定问题设计`的软件。
- 扩展讲解（录播视频）：操作系统 → 第二章；数据库 → 第四章；嵌入式系统及软件 → 第四章；计算机网络 → 第五章；计算机语言、多媒体、系统工程 → 第六章；系统性能 → 第七章。

### 3.2 文件与文件系统

- 文件 = `具有符号名的、逻辑上具有完整意义的一组相关信息项的集合`；文件 = `文件体（真实内容）+ 文件说明（管理信息：文件名、内部标识、类型、存储地址、长度、访问权限、建立/访问时间等）`。
- 文件系统 = `实现文件统一管理的一组软件和数据的集合`；功能：`按名存取、统一用户接口、并发访问和控制、安全性控制、优化性能、差错恢复`。
- 文件分类：按性质用途 → `系统文件、库文件、用户文件`；按保存期限 → `临时文件、档案文件、永久文件`；按保护方式 → `只读、读/写、可执行、不保护文件`；UNIX → `普通文件、目录文件、设备文件`。
- 结构：逻辑结构（用户角度）= `有结构的记录式文件`（记录长度分定长/不定长）+ `无结构的流式文件`（字节流、顺序访问）；物理结构（存放方式）= `连续（顺序）、链接（串联）、索引、多个物理块的索引表`。
- 存取方法：`顺序存取和随机存取`。
- 外存空闲空间管理：`空闲区表`（适用连续结构）/ `位示图`（每位对应一个物理块，0 空闲、1 占用）/ `空闲块链` / `成组链接法`（UNIX 采用）。
- 链接：`硬链接`（两个目录表目指向同一索引结点，`不利于删除`）；`符号链接`（建立新文件或目录，与原文件/目录路径名映射）。
- 保护：常采用`存取控制`——`存取控制矩阵、存取控制表（LINUX 使用）、用户权限表、密码`。

### 3.3 中间件

- 中间件 = `应用软件与各种操作系统之间使用的标准化编程接口和协议`，`承上启下`，使应用开发`独立于硬件和操作系统`。
- 八大类：`通信处理（消息）、事务处理（交易）、数据存取管理、Web 服务器、安全、跨平台和架构、专用平台、网络`（网络类含网管、接入、网络测试、虚拟社区、虚拟缓冲等）。

### 3.4 构件

- 构件（组件）= `自包容、可复用的程序集`，`向外提供统一的访问接口`，外部只能通过接口访问。
- 构件组装模型（搭积木式开发）：`设计构件组装 → 建立构件库 → 构建应用软件 → 测试与发布`。
- 主流商用构件标准：`OMG 的 CORBA（公共对象请求代理架构）`、`Sun 的 J2EE`、`Microsoft 的 DNA`。
- CORBA 分 3 层次：`对象请求代理、公共对象服务、公共设施`；底层 `ORB（对象请求代理）`规定分布对象定义（接口）和语言映射，是分布对象系统的"软总线"；中层为公共服务（并发、名字、事务、安全等）；顶层`公共设施`定义构件框架。
- CORBA CCM 构件模型（OMG 制定的用于`开发和配置分布式应用`的服务器端构件模型规范）：`抽象构件模型`、`构件容器结构`（通用运行/管理环境，支持安全、事务、持久状态等服务集成）、`构件的配置和打包规范`。
- J2EE：同时支持`RMI（远程方法调用）`和`IIOP（互联网内部对象请求代理协议）`；服务器端有`Java Servlet、JSP、EJB`等形式；EJB 中 Bean 分`会话 Bean（维护会话）和实体 Bean（处理事务）`；通常`Servlet 负责与客户端通信、访问 EJB，JSP 产生页面传回客户端`。
- DNA 2000：融合`最先进的分布式计算理论和思想`（事务处理、可伸缩性、异步消息队列、集群）；`Microsoft 的 DCOM/COM/COM+ 技术在 DNA 2000 分布式计算结构基础上，展现了一个全新的分布构件应用模型`。
- COM：主要为`本地的对象连接与嵌入应用服务`；DCOM/COM/COM+ 将其扩充为`面向服务器端分布应用的业务逻辑中间件`。
