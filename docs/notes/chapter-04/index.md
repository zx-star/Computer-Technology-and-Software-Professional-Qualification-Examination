## 1 第二版教材 2.4 嵌入式内容

> 本章历年偶尔考查，通常 2～3 分；重点掌握嵌入式系统组成、特点、体系结构和安全攸关标准。

**嵌入式系统定义**

嵌入式系统是`以应用为中心、以计算机技术为基础`，将可配置、可裁减的软件和硬件集成为一体的专用计算机系统，必须满足应用对`功能、可靠性、成本、体积、功耗`等方面的严格要求。

**系统组成**

`嵌入式处理器 + 相关支撑硬件 + 嵌入式操作系统 + 支撑软件 + 应用软件`。

- 嵌入式处理器：能抵抗恶劣环境，按环境要求分为`民用级、工业级、军用级`，工作温度分别为 0～70℃、-40～85℃、-55～150℃。
- 支撑硬件：处理器以外的硬件，包括存储器、定时器、总线、I/O 接口和专用硬件。
- 嵌入式操作系统：运行在嵌入式系统中的基础软件，重点特征是`实时性、可裁减性、安全性`。
- 支撑软件：为应用软件提供公共服务、开发和调试能力。
- 应用软件：为完成系统特定目标而开发的软件。

**嵌入式系统特点**

记忆关键词：`专用性强、技术融合、软硬一体且软件为主、资源少、代码固化、专用开发工具、高性价比和强实时性、安全可靠要求高`。

**分类与体系结构**

- 按实时性：`嵌入式实时系统 / 非实时系统`；实时系统再分为`强实时 / 弱实时`。
- 按安全性：`安全攸关系统 / 非安全攸关系统`。
- 运行与开发环境：运行在`目标机`，开发在`宿主机`。
- 5 层结构：`硬件层、抽象层、操作系统层、中间件层、应用层`。
- `BSP（板级支持包）`属于抽象层，是面向硬件的驱动软件，为上层操作系统提供硬件管理支持。

**嵌入式软件特点**

`可剪裁性、可配置性、强实时性、安全性、可靠性、高确定性`。其中：安全性强调规定条件和时间内不发生事故；可靠性强调规定条件和时间内执行所需功能；高确定性强调运行时间、状态和行为预先设计，不能随意变化。

## 2 补充：嵌入式微处理器

嵌入式软件采用`宿主机开发、目标机运行`的交叉开发方式：在 PC 或工作站上使用专用工具生成二进制代码，再下载到目标机或固化到目标机存储器中。

**冯·诺依曼 vs 哈佛结构**

| 对比项 | 冯·诺依曼结构 | 哈佛结构 |
| --- | --- | --- |
| 存储器 | 程序和数据共用一个存储器 | 程序存储器、数据存储器相互独立 |
| 总线 | 一套地址总线和数据总线 | 两套独立的地址总线和数据总线 |
| 访问方式 | 先取指令，再取操作数，串行访问 | 可在一个机器周期内同时取指令和操作数 |
| 结果 | 传输通道容易形成瓶颈 | 数据吞吐率约提高 1 倍 |

**处理器分类**

- 按字长：`4、8、16、32、64 位`；16 位及以下通常称嵌入式微控制器，32 位及以上通常称嵌入式微处理器。
- 按集成度：一般用途型微处理器、单芯片微控制器。
- 按用途：`MCU、MPU、DSP、SoC`。

**MCU、MPU、DSP、SoC**

- `MCU`：典型代表是单片机，片上外设丰富，适合控制；特点是单片化、低功耗、低成本、高可靠。
- `MPU`：由通用 CPU 演变而来，通常 32 位以上；只保留与嵌入式应用紧密相关的功能硬件，常见 ARM、MIPS、PowerPC。
- `DSP`：专用于信号处理，采用`哈佛结构、流水线处理`，适合数字滤波、FFT、谱分析，速度可达最快 CPU 的 10～50 倍。
- `SoC`：追求系统最大集成，软硬件无缝结合，可在芯片内集成操作系统代码模块和完整系统。

**多核处理器**

多核是多个处理器内核集成在一枚芯片中，可降低功耗和体积，并支持多进程、多线程并发。

- `SMP（对称多处理）`：内核相同，共享处理任务，性能约为单处理器的 2 倍。
- `AMP（非对称处理）`：内核不同，各自负责特定功能，由软件协调分担任务。
- `全局队列调度`：所有 CPU 共享一个任务等待队列，核心利用率较高。
- `局部队列调度`：每个 CPU 维护自己的任务队列，减少 CPU 间切换。

**嵌入式只读存储器**

按可修改方式记忆：

1. `MASK ROM`：批量制造，内容永久不能修改，成本低。
2. `PROM`：可写入一次，出厂内容通常全为 1，写入单元变为 0。
3. `EPROM`：用紫外线擦除，擦除后可重新编程，芯片有透明窗口。
4. `EEPROM`：用电信号擦除和写入，擦除电压约 20V，可用于 PnP 接口。
5. `Flash`：可直接在主机板上修改，断电不丢失；写入前需先擦除，写入速度较慢。

## 3 补充：嵌入式操作系统

**EOS 定义与职责**

EOS 通常包括`底层驱动、系统内核、设备驱动接口、通信协议、图形界面和标准化浏览器`等，负责`软件和硬件资源分配、任务调度、控制、协调并发活动`。

**EOS 分类**

- `嵌入式实时操作系统`：面向控制、通信等领域，如 VxWorks、Nucleus、μC/OS-II、嵌入式 Linux、Windows Embedded。
- `非实时嵌入式操作系统`：面向消费电子，如 Android、iOS、WinCE。

**EOS 五个特点**

`微型化、代码质量高、专业化、实时性强、可裁减和可配置`。

**嵌入式实时系统**

嵌入式实时系统是完全嵌入受控器件内部、面向特定应用的专用计算机系统。运行前必须具备`确定性和可预测性`：

- `可预测性`：运行前可以预测系统的功能、响应特性和执行结果。
- `确定性`：给定初始状态和输入条件后，能在确定时间内给出确定结果。

**RTOS 及实时性分类**

RTOS 能在外界事件或数据产生时`及时响应`，在规定时间内完成处理，并保证实时任务协调运行；主要特点是`及时响应和高可靠性`。

- `硬实时`：规定时间内必须完成操作，由系统设计保证。
- `软实时`：按任务优先级尽可能快地完成操作。

嵌入式软件开发相较传统软件开发：更强调`软硬件协同效率与稳定性`，开发结果通常要固化，需专用开发工具、目标系统和测试设备，并且对`实时性、安全性、可靠性和代码规模`要求更高。安全攸关软件还要满足相应领域的设计与代码审定要求。模块化设计就是按功能把大程序拆分为多个模块。

## 4 补充：嵌入式软件设计

### 4.1 DO-178B 核心内容

DO-178B 的目的：为机载软件提供适航指导。核心记忆：`目标、活动、证据（软件生命周期数据）`。

软件安全等级为 `A～E`，目标数量依次为：`66、65、56、28、0`；等级越高，失效后果越严重，要求达到的目标越多。

软件生命周期过程可记为：

- 软件计划过程：规划、协调生命周期活动，制定计划和标准。
- 软件开发过程：`软件需求、软件设计、软件编码、集成`。
- 软件综合过程：`软件验证、软件配置管理、软件质量保证、审定联络`。

软件生命周期数据包括文档、代码、报告、记录等生命周期内产生的产品。

### 4.2 DO-178 与 CMMI

| 对比项 | CMMI | DO-178 |
| --- | --- | --- |
| 视角 | `过程改进` | `适航审定` |
| 关注点 | 组织整体软件能力 | 项目软件质量对安全性的影响 |
| 组成 | `实践` | `目标、活动、数据` |
| 覆盖范围 | 个人、项目、组织，范围更广 | 聚焦软件，过程范围更小 |
| 特点 | 综合系统、软件、硬件视角 | 面向安全攸关软件，目标清晰、要求具体 |

### 4.3 交叉开发环境与交叉编译/调试

- **交叉平台开发环境三要素**：`交叉开发工具和实用程序`（宿主机+目标机）、`高性能、可裁剪的实时操作系统`（目标机）、`宿主机-目标机通信`（以太网/USB/串口）。
- **交叉编译**：`在一个平台上生成可以在另一个平台上执行的代码`；不同 CPU 指令系统不同 → 需要相应编译器；嵌入式开发要`借助宿主机（通用计算机）编译出目标机的可执行代码`。
- **交叉调试**：`调试器运行在宿主机通用操作系统之上`，`被调试进程运行在目标机的嵌入式操作系统中`，两者通过`串口或网络`通信；调试器可控制/访问被调试进程、读取并改变其运行状态。
